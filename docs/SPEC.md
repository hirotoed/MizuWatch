# MizuWatch システム仕様書

最終更新: 2026-08-16  
対象: MizuWatch v1

## 1. 目的

MizuWatch v1 は、河川・湖・ため池などの**淡水域**を対象とした低コスト水上環境観測システムである。

水温・pH・EC（電気伝導度）・位置情報を取得し、ローカル保存、通信、Web 可視化までを一続きで実現する。

研究面では、低価格センサーを基準機器と比較し、精度・個体差・応答遅れ・ドリフト等を評価することで、**どの条件なら研究データとして利用できるか**を明らかにすることを重視する。

## 2. v1 の対象範囲

### 対象水域

- 河川
- 湖
- ため池

### v1 対象外

- 汽水域
- 沿岸部
- 海水域
- 自律航行
- ソーラー充電
- DO（溶存酸素）
- 濁度

DO・濁度は v1.1 以降の追加候補とする。

## 5. v1 センサー構成

| 測定項目 | センサー候補 | 接続 | 状態 |
|---|---|---|---|
| 水温 | DS18B20 | 1-Wire | 採用方向 |
| pH | DFRobot SEN0169-V2 | Analog | 第一候補 |
| EC | DFRobot SEN0706 (K=1) | RS485 / Modbus RTU | 第一候補 |
| 位置 | GPS モジュール | 未定 | 要選定 |
| 気温・湿度・気圧 | BME280 | I2C | 補助データ用 |

センサー候補は比較試験の結果によって変更する可能性がある。

## 6. 測定要求仕様

### 6.1 水温

| 項目 | 要求仕様 |
|---|---|
| v1 運用範囲 | 0〜40 ℃ |
| Web 表示分解能 | 0.1 ℃ |
| 定量研究用途の暫定目標 | MAE ≤ 0.3 ℃ |
| 95%誤差の暫定目標 | ±0.5 ℃以内 |
| Screening 用途 | おおむね ±1 ℃以内 |
| 記録周期 | 1 秒 |
| 候補 | DS18B20 |

DS18B20 の公称精度だけでは上記 MAE を保証できないため、基準温度計との比較試験で採用可否を判断する。

### 6.2 pH

| 項目 | 要求仕様 |
|---|---|
| v1 運用保証範囲案 | pH 4.0〜10.0 |
| Web 表示分解能 | 0.01 pH |
| 定量研究用途の暫定目標 | MAE ≤ 0.15 pH |
| 95%誤差の暫定目標 | ±0.30 pH以内 |
| Screening 用途 | おおむね ±0.5 pH以内 |
| 記録周期 | 1 秒 |
| 候補 | DFRobot SEN0169-V2 |

#### 校正

SEN0169-V2 を使用する場合、初期方針は以下とする。

- pH 4.00 標準液
- pH 7.00 標準液
- 上記による 2 点校正
- pH 9〜10 付近の標準液は独立した精度確認に使用する

校正に使用した標準液と評価用標準液を分け、校正点以外での誤差も確認する。

#### 応答遅れ

1 秒ごとに値を保存できても、1 秒ごとに新しい水質へ追従できるとは限らない。

pH センサーについて T50 / T90 / T95 を実測し、移動速度との関係を評価する。

```text
応答遅れによる空間方向のずれ L = 移動速度 v × 応答時間 τ
```

最大観測速度や停船後の待機時間は、実測 T90 をもとに決定する。

### 6.3 EC

| 項目 | 要求仕様 |
|---|---|
| v1 運用範囲 | 1〜2000 µS/cm |
| Web 表示分解能 | 1 µS/cm |
| 定量研究用途の暫定目標 | 相対 MAE ≤ 5% |
| Screening 用途 | 相対誤差おおむね ≤ 10% |
| 記録周期 | 1 秒 |
| 候補 | DFRobot SEN0706 (K=1) |

#### 校正・検証

SEN0706 を使用する場合、初期方針は以下とする。

- 1413 µS/cm 標準液を主要な校正点として使用
- 84 µS/cm など別濃度の標準液を独立検証に使用
- 温度補償条件を記録する
- 低 EC 域では相対誤差が大きくなる可能性があるため、利用可能範囲を実験で決定する

EC の利用可能範囲はカタログ値だけで決めず、実測した Bias・MAE・RMSE 等から決定する。

## 7. データ取得・保存周期

### 基本方針

- センサー取得: **1 Hz（1 秒周期）**
- SD カード保存: **1 Hz**
- サーバー送信: **10 秒周期を初期値**
- Web 更新: **10 秒周期を初期値**

```text
センサー
  ↓ 1 秒
生データ取得
  ↓
SD カードへ保存
  ↓ 10 秒単位
送信用データ生成
  ↓
LTE-M 等
  ↓
サーバー / DB
```

通信周期は消費電力・通信量・実験結果を見て変更可能とする。

## 8. 保存データ

測定値だけではなく、測定品質を評価できるメタデータも保存する。

最低限、以下を保存する。

```text
device_id
timestamp
latitude
longitude

water_temperature
ph
ec

air_temperature
humidity
pressure

battery_voltage
GPS quality / accuracy
communication_status

sensor_id
calibration_id
measurement_status
quality_flag
```

正式 API の wire 形式は camelCase、DB 列は snake_case とし、項目、検証範囲、取得レスポンスとの対応は [`API_DATABASE_AUTH.md`](API_DATABASE_AUTH.md) を正本とする。

## 9. 品質フラグ

将来的に各データへ品質フラグを付与する。

### 暫定案

- **A: Research quantitative**  
  校正状態・応答状態・精度条件を満たし、定量研究用途に使用可能。

- **B: Screening / trend**  
  絶対値の精密利用には注意が必要だが、傾向把握や異常候補の抽出には利用可能。

- **C: Invalid / caution**  
  校正期限、応答未安定、センサー異常等により利用に注意が必要。

A/B/C の具体的判定条件は比較検証結果をもとに決定する。

## 10. 比較検証要求

各センサーについて、原則として**最低 3 個体**を比較対象とする。

主な評価項目:

- Mean Bias
- MAE
- RMSE
- 個体間ばらつき
- T50 / T90 / T95
- ドリフト
- ヒステリシス
- 温度依存性
- 移動速度による空間誤差
- 欠測率
- 長時間運用時の安定性

研究上の目的は、単純に「合格 / 不合格」を決めることではなく、**各センサーがどの条件・用途なら十分な品質を持つかを明らかにすること**とする。

## 11. 通信

### 方針

- LTE-M を有力候補とする
- 通信圏外でも観測を継続できること
- 通信断中のデータは SD カードへ保存する
- 通信復旧後に未送信データを再送する

### 未決定

- LTE-M モジュール
- SIM
- 通信プロトコル

## 12. 正式バックエンド

- API: Supabase Edge Functions（TypeScript）
- DB: Supabase PostgreSQL
- Web 認証: Supabase Auth（招待制メール + パスワード）
- 観測機認証: 機体ごとの 256 bit token
- 重複防止: UUID v7 `messageId` と DB 一意制約
- リージョン: Tokyo (`ap-northeast-1`)

API / DB の詳細仕様は [`API_DATABASE_AUTH.md`](API_DATABASE_AUTH.md) を正本とする。

## 13. 電源

### 方針

- リチウムイオン電池を使用予定
- バッテリー電圧 / 残量を記録する
- 実測消費電力から連続稼働時間を算出する

### 注意

SEN0706 を採用する場合、Pico W の 3.3 V 系とは別にセンサー用電源系が必要になるため、電源回路設計時に考慮する。

## 15. 仕様決定ルール

- カタログ性能だけで最終採用を決めない。
- 低価格センサーは基準機器との比較結果をもとに採用する。
- 実験結果が本仕様書の仮定と矛盾した場合は、実験結果を優先して仕様を更新する。
- PCB 発注前に、モジュール構成でセンサー・通信・電源を実機検証する。
